# Scope task-level outcome learning

Personal OS may observe the current user-authored main Session, but automatic curation is allowed only at a credible Task completion boundary. A completed turn is evidence inside a Task, not a durable boundary. Clarification, approval, retry, commit, push, verification, and small correction turns remain in the same Task Span when they preserve the objective.

`balanced` creates one reviewable Outcome Proposal and performs no Domain mutation before acceptance. `proactive` may apply only high-confidence candidates through the same proposal pipeline and must leave ambiguous candidates pending with an undo path. `off` performs no automatic Task analysis; explicit finalization remains available. No automatic mode creates Capture—unresolved material reaches Inbox only through an explicit user action.

Subagent, automated, and system Sessions are excluded. Users may exclude individual Sessions or Workspaces, and cross-Workspace learning remains separately configurable because Host-level Session access is trusted infrastructure rather than proof of user authorization. Historical processing is always explicitly initiated and reconstructs Task Spans incrementally; startup scanning and turn-level Capture creation are prohibited.

Task Span and Outcome Proposal are reconstructible operational state, not Markdown Domain Facts. Accepted objects and grouped Timeline Activity retain Session, Task, Outcome, Workspace, and event-range provenance without copied transcripts, reasoning, Tool parameters, or raw file contents.
